# WorldTree web preview

A mobile ecological explorer for procedural world building, migrated from the supplied v0.6 Python prototype. Next.js 16, TypeScript, React and MapLibre GL JS. The application exports static files for Vercel; no Python process, desktop server, API keys or database is required at runtime.

## Develop and validate

Node.js 24 is used for this project. Install with `npm ci`, then `npm run dev`.

```
npm run lint
npm run typecheck
npm test
npm run test:python
python scripts/verify_data.py
npm run build
```

`npm run build` builds the lookup worker, copies MapLibre’s matching worker, and exports the website to `out/`. To inspect the actual production output locally, run `npm run preview:local`. `next start` is not supported for a static export.

Python is only needed for prototype tests and geographic data ingestion. Install the versions in `scripts/requirements-data.txt` first. The original prototype and its 15 tests are preserved under `prototype/worldtree/`. The web catalog is byte-for-byte identical to the original JSON files; 148 golden cases generated by the original Python verify catalog parity.

## Use

Tap or click the map to select coordinates. Drag to pan; pinch, scroll or use the large zoom controls to zoom. Presets include Seattle, Atlanta and Tokyo. Search the 18 named catalog regions or enter any `latitude, longitude` pair. The search is local and does not provide a worldwide address geocoder. Use **More regions** for the other 15 profiles. The Natural and Urban / planted tabs use separate catalog pools. Some regions have no urban pool, and the app says so.

The Biomes switch controls a simplified RESOLVE overlay. Catalog areas shows the coarse rectangular species-candidate areas; these are not species ranges. Street detail uses OpenStreetMap’s public raster tiles from zoom 4 upward and needs internet. The bundled Natural Earth geographic basemap, ecoregion overlay, catalog and previously downloaded lookup tiles can be cached offline after a first online visit. This is partial offline support, not a predownload of the whole planet. WebGL and a modern browser supporting workers and DecompressionStream are required for the complete map experience. Search and catalogs remain usable if WebGL fails.

## Ecological data and limits

- 18 original locality profiles, 62 unique taxa and 71 habitat associations are preserved. All species associations are provisional: zero verified native ranges, zero verified ecoregion joins, and no species-level citations or accepted taxon identifiers in the prototype.
- Names, ecological roles, origin labels and asset archetypes come from the prototype. A “Native candidate” label is not a verified occurrence. The reference portals are research starting points, not supporting citations for individual species. No abundance percentages or probabilities are shown.
- Selection preserves the original bounding-box algorithm, including choosing the smallest overlapping profile. Geographic polygon lookup never assigns species by biome or nearest region. Unsupported locations return an honest empty state.
- RESOLVE is a published, dated ecological classification of potential terrestrial context. It is not current land cover, an inventory of existing trees, or a survey-accurate boundary. Coastal points and inland water can be outside a land polygon.
- Urban pools exist only for Seattle, Atlanta and Tokyo in the supplied catalog. Other regions return no curated urban candidates. Natural Tokyo has its supplied candidate pool.

## Geographic provenance and reproduction

The original [RESOLVE 2017 archive](https://storage.googleapis.com/teow2016/Ecoregions2017.zip) was downloaded from the link on the [RESOLVE map](https://ecoregions.appspot.com/). Attribution: Dinerstein, E. et al. (2017), *An Ecoregion-Based Approach to Protecting Half the Terrestrial Realm*, BioScience 67(6):534–545, [doi:10.1093/biosci/bix014](https://doi.org/10.1093/biosci/bix014). Ecoregions 2017 © RESOLVE. Licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); see [the dataset catalog](https://developers.google.com/earth-engine/datasets/catalog/RESOLVE_ECOREGIONS_2017).

The source contains 847 records: 846 terrestrial ecoregions plus Rock and Ice. All are retained. CP1252 source attributes are decoded to UTF-8. Shapely `make_valid` repairs 69 invalid source features before clipping; their IDs are recorded in the manifest. Accurate lookup retains source vertices inside 10-degree grid clips without simplification. 463 gzip GeoJSON tiles are versioned in Git, with SHA-256 hashes in `public/data/resolve-2017/manifest.json`. The browser loads the relevant tile in a separate worker, handles holes and multipart polygons, includes boundary points, and keeps up to four decoded tiles in memory. It never uses the display geometry for lookup.

The separate display geometry is simplified twice at 0.035 degrees, with tiny islands allowed to disappear in the second pass, and display coordinates rounded to four decimals. This reduces rendering cost; displayed coastlines and boundaries can differ from lookup results. No source coordinate precision is removed from lookup tiles. The original downloaded archive is excluded from Git because it is 149 MB; its SHA-256 and URL are recorded so it can be verified and downloaded again.

To reproduce (several minutes and approximately 1 GB of memory):

```
python -m pip install -r scripts/requirements-data.txt
python scripts/import_ecoregions.py
python scripts/verify_data.py
```

Natural Earth low-resolution land geometry is preserved from the supplied ZIP and is [public domain](https://www.naturalearthdata.com/about/terms-of-use/). Street tiles are © OpenStreetMap contributors, [ODbL attribution](https://www.openstreetmap.org/copyright); they are fetched on demand and are not downloaded for offline use. MapLibre GL JS is BSD-3-Clause. Fonts use Google Fonts with system-font fallbacks.

## Preview deployment

GitHub repository creation is private by default. Vercel deployment must use a **preview** target (omit `--prod`):

```
npx vercel login
npx vercel deploy --yes --environment preview
```

Vercel should detect Next.js, run `npm run build`, and serve the static export. Never upload `.codex-attachments`, local credentials, the source archive, or `data/raw`. Both ignore files exclude these. A public phone-accessible preview requires Vercel preview authentication protection to be disabled for this project. No production deployment is needed.

**First-deployment constraint observed with Vercel CLI 66.6.0:** an empty project's first deployment is forced to Production. An explicit `--environment preview` is refused with `first_deployment_production`. Do not override this with `--prod` for WorldTree. Deployment is pending user approval for an empty, data-free Production baseline followed by the actual WorldTree Preview. The newly created `worldtree-web-preview` Vercel project currently has no deployments; preview authentication protection was disabled as requested for public phone access. No WorldTree production deployment has been made.

For a production-output local preview use `npm run preview:local`. The project-level Vercel headers keep the service worker fresh and versioned geographic files cacheable. Increase the service worker cache version when modifying the ecological dataset or lookup worker.
