# Ground mapping Phase 1

## Existing architecture and integration

The existing `WorldMap.tsx` uses MapLibre with Natural Earth land, simplified RESOLVE polygons, optional OSM raster streets and a shared `selected: Place` callback. `Explorer.tsx` owns that selection, named presets, coordinate search and the independent worker-based ecological lookup. The worker uses accurate geographic lookup assets; this pass does not change it or any suitability calculation. `public/sw.js` already caches visited same-origin `/data/` resources, so versioned ground assets reuse that policy; no new service worker is introduced. Data promises are reused within the page session. Existing ecological cache contents are unchanged.

GroundLayers adds Trees / Land cover / Soil views to the same map, using the same selected coordinate and marker. Trees restores the original ecology overlays. The regional raster sources draw at zoom 8 and above; map overview and smaller screens fetch only small display images, not global rasters. Inspector arrays load on the first ground-layer selection, once per session. Street requests remain network-only under the existing policy. The Trees layer describes potential ecological context; land cover describes classified surface cover and soil is a model prediction. None modifies species suitability.

## Sources, access, rights

- **ESA WorldCover 2021 v200**: [official access and license](https://esa-worldcover.org/en/data-access). Global categorical baseline, nominal 10 m, EPSG:4326 COGs, CC BY 4.0. This demonstration reads only a Seattle window from the public AWS N45W123 tile by range requests. The numeric pixel values are retained losslessly as RLE; rendering uses a muted, modified palette and a reduced 512×512 nearest-neighbour Web Mercator image. Attribution: © ESA WorldCover project 2021 / Contains modified Copernicus Sentinel data (2021) processed by ESA WorldCover consortium. WMS is for visualization, not numeric analysis; Terrascope access failed local certificate validation, so it is not a runtime dependency. No TLS verification was disabled.
- **ISRIC SoilGrids 2.0**: [license](https://isric.org/explore/soilgrids/), [access and REST outage notice](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_02.html), [units and uncertainty](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_01.html). CC BY 4.0; 250 m predictions at 0–5 cm, mean/Q05/Q95 for sand, silt, clay and organic carbon. WCS GetCoverage successfully provided bounded Interrupted Goode Homolosine rasters. Integer texture values are divided by 10 to percent; organic-carbon values by 10 to g/kg. The lookup grid is reprojected nearest-neighbour into 48×48 regional WGS84 cells; this does not add source detail. Display uses a separate 256×256 sand image in Web Mercator. Model release is not an observation year; source URLs, retrieval time and response hashes are saved. Quantiles show prediction uncertainty, not field measurement errors.
- **Copernicus LC100 Collection 3**: [band definitions/access](https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Data/clms/land-cover-and-land-use-mapping/global-dynamic-land-cover/lc_global_100m_yearly_v3.html), [data policy](https://land.copernicus.eu/en/data-policy), [service quotas](https://documentation.dataspace.copernicus.eu/Quotas.html). Investigated 100 m, 2015–2019 fractional grass, shrub, tree and moss/lichen products. Products permit free/open use with attribution. CDSE BYOC access requires authentication/collection selection and service quotas apply. No account credentials, credit-consuming processing or downloads were configured. Fractions remain unavailable rather than fabricated from categorical WorldCover pixels. Future regional preparation can use the documented GeoTIFF/BYOC paths.

## Delivered coverage and costs

Coverage is only longitude **−122.40 to −122.28**, latitude **47.57 to 47.69**, Seattle. Outside this rectangle there are no ground data in this release, including Atlanta and Tokyo. Global product availability is not application coverage. Soil has additional masked urban/water pixels; a zero-total texture triplet is treated as missing, not zero-percent soil. No global high-resolution file is stored.

The complete regional bundle is about **1.12 MB uncompressed**: 937 kB lossless land classes, 116 kB soil numeric data, 59 kB categorical PNG, 2 kB soil PNG and 3 kB metadata. Existing geometry/app assets and optional OSM traffic are additional. One thousand uncached regional downloads would transfer roughly 1.12 GB before compression/cache savings. Static hosting incurs existing provider storage/bandwidth allowances and possible overage, rather than per-click raster compute. No paid service was enabled and no deployment was made. An exact currency estimate requires the hosting account's plan and actual traffic. Global expansion is not costed or provisioned: use bounded per-region numeric tiles, coarse overviews at low zoom and fine COG windows only at high zoom, with explicit cache/version limits before enabling worldwide requests. Do not ship global arrays or use public WCS as an unbounded per-click proxy.

Python rasterio, NumPy and Pillow are import tooling, not application dependencies. The importer caps requests to this rectangle and uses two concurrent WCS requests. Rebuild with `python scripts/import_ground_demo.py`; remote services have no guaranteed availability. Static assets continue to work if those services later fail. A new data revision should use a new versioned path because the existing offline policy is cache-first.

## Validation and limits

- TypeScript passed; three targeted tests passed: lossless RLE pixel count, three independent COG point samples, grid boundary handling/missing coverage and known soil value/unit lookup.
- The independent source samples include Seattle built-up, Lake Union water and a northern sample. WGS84 bounds are carried with both numeric grids; raster images use the same outer corners and are reprojected into Web Mercator before MapLibre placement.
- Desktop capture and actual map tap updated the shared coordinate inspector. Tokyo correctly produced outside-demo coverage. Android-sized 390×844 layout had no horizontal overflow; four browser flows reported no page errors. This is Chromium validation, not a physical Android device test.
- [Land-cover screenshot](../artifacts/wildloom-ground-land.png), [soil screenshot](../artifacts/wildloom-ground-soil.png), [mobile capture](../artifacts/wildloom-ground-mobile.png), [browser validation](../artifacts/wildloom-ground-validation.json).
- Display rasters are deliberately coarser than the source and use nearest-neighbour resampling; inspect the source pixel for numeric classification. WorldCover InputQuality was not imported; no per-pixel classification confidence is asserted.
- Only sand is visualized in Soil mode; silt, clay and carbon are inspected numerically. pH was optional and not imported. USDA texture class is **not derived**: independent predictions may not close, and SoilGrids documents mixed silt particle-size conventions. A validated texture-class adapter is a follow-up, not a label silently inferred from the largest fraction.

## Future inferred ground vegetation extension

`InferredGroundPalette` in `src/lib/ground.ts` is a separate, lightweight contract. A future resolver may combine ecoregion, climate, habitat and occurrence evidence into regional candidate taxa with confidence, sources and method version. It must remain separate from observed classifications and predicted fractions. No categorical grass/shrub/moss class identifies a species. No global species-level ground-vegetation map is claimed, and there is no 3D ground rendering in this phase.
